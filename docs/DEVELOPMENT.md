# Разработка и расширение

## 1. Требования к изменениям

- Сохраняйте совместимость с API 1С-Битрикс, используемым модулем.
- Не добавляйте jQuery в административный контроллер: он переведен на Vanilla JavaScript.
- Для клиентской интеграции используйте уже применяемый API Битрикс (`BX`) там, где это необходимо.
- Не изменяйте поведение массовых операций без теста на копии сайта.
- Не считайте прохождение синтаксических проверок полноценным runtime-тестом.

## 2. Добавление действия-плагина

Встроенные действия находятся в `include/actions/`. При формировании списка модуль подключает PHP-файлы этого каталога, затем выполняет события `GetActionsList` (для совместимости) и `OnGetActionsList`. После этого модуль ищет объявленные классы с префиксом `CME_`, отличные от `CME` и `CME_Plugin`, и проверяет наличие метода-маркера `WDA_PLUGIN`.

Новый класс должен наследоваться от `CME_Plugin` и объявлять:

- `GROUP` — код группы;
- `CODE` — уникальный код действия;
- `NAME` — отображаемое название;
- `AddHeadData()` — подключение необходимых ресурсов и клиентских обработчиков;
- `ShowSettings($IBlockID = false)` — вывод HTML формы параметров;
- `Process($ItemID, $arElement, $Params)` — обработка одного элемента.

Пример каркаса:

```php
<?php

class CME_MyAction extends CME_Plugin
{
    const GROUP = 'GENERAL';
    const CODE = 'MY_ACTION';
    const NAME = 'Мое действие';

    public static function AddHeadData()
    {
        // Подключение ресурсов и клиентских обработчиков при необходимости.
    }

    public static function ShowSettings($IBlockID = false)
    {
        // Вывод HTML настроек. Имена полей формы должны попадать в params[...].
    }

    public static function Process($ItemID, $arElement, $Params)
    {
        // Обработать один элемент.
        // Вернуть true при успехе и false при ошибке.
        return true;
    }
}
```

Используйте уникальные имена класса и `CODE`. Допустимые встроенные группы: `GENERAL`, `IMAGES`, `PRICES`, `OTHERS`. Новые группы можно добавлять обработчиком `OnGetActionsGroup`, получающим массив групп по ссылке.

### Подключение внешнего плагина

Внешний PHP-файл можно подключить обработчиком события модуля `OnGetActionsList` либо из `/bitrix/php_interface/init.php`. Пример регистрации:

```php
AddEventHandler(
    'codematrix.elemmass',
    'OnGetActionsList',
    'myElemmassRegisterAction'
);

function myElemmassRegisterAction()
{
    require_once $_SERVER['DOCUMENT_ROOT']
        . '/bitrix/php_interface/mass_plugins/MyAction.php';
}
```

Убедитесь, что файл подключается до того, как модуль собирает список объявленных классов. Не допускайте конфликтов имен классов и кодов действий.

## 3. Параметры и обработка элемента

Метод `Process` получает:

- `$ItemID` — ID элемента инфоблока;
- `$arElement` — поля элемента и массив `PROPERTIES`;
- `$Params` — параметры формы действия.

При реализации:

- проверяйте наличие и тип каждого параметра;
- учитывайте одиночные и множественные значения свойств;
- проверяйте результат API Битрикс;
- не выводите диагностический текст в AJAX-ответ;
- записывайте подробности ошибки в журнал;
- возвращайте `true` только при успешной обработке;
- не используйте состояние браузерной сессии как единственный источник данных.

Операции могут выполняться из браузера или через Cron. В CLI-режиме нет обычного браузерного контекста, поэтому не полагайтесь на DOM, JS-события или пользовательскую сессию.

## 4. Клиентские события

Встроенный интерфейс генерирует события:

- `onWdaAfterIBlockChange`;
- `onWdaAfterActionChange`;
- `onWdaBeforeSubmit`.

Для отмены отправки в обработчике `onWdaBeforeSubmit` можно установить `WdaCanSubmit = false`. В обработчиках смены инфоблока и действия доступна глобальная переменная `WdaCurrentAction`.

Для собственных обработчиков используйте API событий Битрикс, не добавляя зависимость от jQuery.

## 5. Локальные проверки и CI

Перед отправкой изменений:

1. Проверьте синтаксис измененных PHP-файлов.
2. Проверьте синтаксис измененного JavaScript.
3. Проверьте встроенный JavaScript в PHP-страницах, если меняли его.
4. Убедитесь, что в административном JS не появились обращения к jQuery.
5. Проверьте diff на случайное изменение путей, ID модуля и имен событий.
6. Запустите GitHub Actions и изучите результат каждого job.

Workflow `.github/workflows/php-compatibility.yml` содержит автоматические проверки PHP и JavaScript. Матрица CI — это проверка синтаксиса и статических ограничений, а не гарантия работы на всех версиях PHP и конфигурациях Битрикс.

## 6. Ручная проверка на тестовом сайте

Минимальный сценарий приемки:

- установка и удаление модуля на отдельном тестовом сайте;
- открытие страницы под пользователем с правом только чтения и под пользователем с правом записи;
- выбор инфоблока, раздела и нескольких разделов;
- фильтрация по полю, свойству и дате;
- запуск безопасного действия на небольшой выборке;
- проверка прогресса, отмены и итоговых счетчиков;
- сохранение, повторная загрузка и удаление профиля;
- запуск тестового профиля из Cron;
- проверка журналов PHP/Битрикс и сетевых ответов AJAX.

Отдельно проверяйте торговые предложения, связанные товары, множественные свойства и файловые поля: поведение может отличаться от простых элементов инфоблока.

# Архитектура модуля

## 1. Общая информация

- ID: `codematrix.elemmass`
- Класс основного API: `CWDA` в корневом `include.php`
- Базовый класс расширений: `CME_Plugin`
- Хранилище профилей: `CME_Profile`
- Административная точка входа: `admin/wda.php`
- Страница профилей: `admin/wda_profiles.php`
- Клиентский сценарий: `install/js/codematrix.elemmass/codematrix.elemmass.js`

Модуль использует административное API 1С-Битрикс, модуль инфоблоков и API каталога для операций, связанных с товарами и ценами.

## 2. Структура каталогов

| Путь | Назначение |
| --- | --- |
| `admin/` | Административные страницы операций и профилей |
| `classes/general/` | Общие классы, включая базовый класс плагина |
| `classes/mysql/` | Реализация хранилища профилей для MySQL |
| `include/actions/` | Встроенные действия массовой обработки |
| `install/` | Установщик, SQL, версия и копируемые ресурсы |
| `install/js/` | Клиентский JavaScript административной страницы |
| `install/themes/` | Стили административного интерфейса |
| `lang/ru/` | Русские языковые сообщения |
| `docs/` | Актуальная документация и исторический материал |
| `.github/workflows/` | CI-проверки |

## 3. Инициализация

`include.php` задает константу `WDA_MODULE`, подключает языковые сообщения и регистрирует автозагрузку `CME_Plugin` и `CME_Profile`. Основная логика выборки, фильтрации, списка действий и выполнения находится в классе `CWDA`.

`install/index.php` выполняет установку/удаление: SQL-операции, регистрацию модуля и копирование административных ресурсов. Идентификатор файловых ресурсов и административных страниц соответствует `codematrix.elemmass`.

## 4. Сценарий выполнения

1. Административная страница проверяет права пользователя на модуль и наличие `iblock`.
2. Формирует список инфоблоков, полей, свойств и доступных действий.
3. Пользователь задает разделы и фильтры, выбирает действие и его параметры.
4. Сервер преобразует условия в фильтр API инфоблоков.
5. При старте сохраняются параметры текущего процесса и счетчики в сессии.
6. Обработка выбирает элементы в порядке возрастания ID и вызывает статический метод `Process($ElementID, $arElement, $Params)` класса действия.
7. Один HTTP-шаг ограничен константой `WDA_STEP_DURATION` (10 секунд). При необходимости клиент запрашивает продолжение, пока сервер не вернет завершение.
8. Счетчики обработанных, успешных и завершившихся ошибкой элементов возвращаются клиенту.

Возвращаемое значение метода действия трактуется как успешный/неуспешный результат для счетчика. Действие должно само корректно обрабатывать ошибки и возвращать осмысленный boolean-результат.

## 5. Клиентская часть

Административный интерфейс использует Vanilla JavaScript для работы с DOM, сериализации формы, AJAX-запросов, прогресса и загрузки профилей. jQuery не является зависимостью клиентского контроллера.

При этом модуль использует API ядра Битрикс, включая `BX` и `BX.addCustomEvent`, а также подключаемые административные ресурсы Битрикс. Поэтому «без jQuery» не означает «без JavaScript API Битрикс».

Встроенные события интерфейса, используемые кодом действий:

- `onWdaAfterIBlockChange` — после смены инфоблока;
- `onWdaAfterActionChange` — после смены действия;
- `onWdaBeforeSubmit` — перед запуском операции; обработчик может установить `WdaCanSubmit = false`.

Клиентский код расположен в `install/js/codematrix.elemmass/codematrix.elemmass.js`.

## 6. Профили и база данных

Класс `CME_Profile` реализован в `classes/mysql/CME_Profile.php`. SQL-схема создается из `install/db/mysql/install.sql`. Профиль хранит параметры выборки и операции, в том числе инфоблок, разделы, фильтр и параметры действия.

Текущая реализация хранилища в репозитории — MySQL. Наличие SQL-скрипта для другого типа БД не следует предполагать без отдельной реализации класса хранилища.

## 7. Cron

`cron.php` определяет корень сайта, подключает `prolog_before.php`, включает модуль и вызывает `CWDA::CronExec($argv)`. Метод разбирает аргументы командной строки, находит профиль по параметру `profile`, восстанавливает настройки и выполняет действие без интерактивной административной страницы.

CLI-режим отличается от браузерного: нельзя полагаться на состояние пользовательской сессии и браузерные события. Плагин должен учитывать режим запуска.

## 8. Права

Административная страница разрешает просмотр при праве модуля не ниже `R`; запуск AJAX-операции и сохранение профиля доступны только при праве не ниже `W`. Настройки прав управляются через стандартную страницу прав модуля.

## 9. Ограничения подтверждения

CI выполняет автоматические статические проверки PHP/JavaScript и проверку отсутствия jQuery в соответствующих участках административного интерфейса. Это не доказывает корректность всех бизнес-сценариев на любой конфигурации Битрикс, каталога, торговых предложений или сторонних модулей. Полная приемка требует проверки на тестовом сайте с реальными типами инфоблоков и данными.
